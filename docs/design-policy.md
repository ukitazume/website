# MTK SH サイトのデザイン方針

更新日 2026年10月14日

MTK SHは、公開済みアプリを一覧し、機能・対応言語・サポートを確認してApp Storeへ進めるサイト。アプリの画像と内容を主役にし、ブランドは短い文字ロゴと控えめな見出しで示す。現在はSitesの本人限定プレビュー。正式公開先はCloudflareを予定している。

## ブランドと文章

- 表記は大文字・半角スペース入りの **MTK SH** に統一する。文字ロゴを基本とする。
- 個人名をブランドや紹介文の前面に出さない。法人名、契約主体、App Storeの販売者情報は別に管理する。
- ブランド名を巨大な見出しで繰り返さない。トップには短い英語の一文、または2〜3行の具体的な説明を置く。
- 機能、対象、操作を具体的に書く。「日々に小さな可能性を」のような抽象的な日本語コピーを重ねない。
- アプリが実際に提供することを説明し、未公開の機能、効果、対応言語を追加しない。

トップのプレビュー案は **Some tools. Some toys.**。集中や日々の記録に使う道具と、ゲームをまとめる短い英語として扱う。

## 参考にする要素

ユーザー提供のアプリ一覧参考画像2枚と詳細参考画像1枚を起点とする。Fuzzcoの一覧は、画像と短い説明の反復、余白、軽い語り口を参考にする。Paradigmの一覧と詳細は、明快な分類と、左に一覧の気配を残す詳細表示を参考にする。

レイアウトの考え方を取り入れ、参考サイトのロゴ・作品画像・文言を流用しない。MTK SHでは各アプリの実素材を使用する。

## ページ構成

| ページ | 役割 |
| --- | --- |
| アプリ一覧 | 公開済み3アプリ・審査中のFramesとWIWS、カテゴリ絞り込み |
| アプリ詳細 | 概要、機能、対応環境、言語、実画面、FAQ、App Storeへのリンク |
| サポート一覧 | アプリごとの使い方とポリシーへの入口 |
| アプリ別サポート | 使い方、トラブル対処、問い合わせ先 |
| アプリ別プライバシー | データの取り扱いと元の適用日 |

一覧から詳細、詳細からApp Store・サポート・ポリシーへ進める。詳細は独立URLを持つ静的ページとし、モーダルを開かないと情報を読めない構成にはしない。

## 色と書体

| 用途 | 設定 |
| --- | --- |
| 背景 | 温かみのある白 `#fbfaf7` |
| 本文 | 墨色 `#272822` |
| 補助文字 | `#76766d`。小さい本文ではより濃い色を使う |
| 区切り線 | `#dbdcd4`、1px |
| 操作アクセント | `#d3492d`、ホバー・フォーカスなどに限定 |
| UIとブランド | OS標準のサンセリフ、日本語はゴシック体 |
| アプリ名 | 一覧カードとアプリ詳細ではセリフ体 |

装飾のための大きな丸角、過剰な影、光るボタン、全面の動画は使わない。影はアプリ画像に必要な奥行きを与える範囲とする。

## 見出しと余白

トップのH1を最大88pxから、デスクトップ36px・モバイル28pxへ縮小する。文字の大きさで画面を埋めず、アプリ一覧が早く見える高さにする。

| 要素 | デスクトップ | 760px以下 |
| --- | --- | --- |
| 文字ロゴ | 20px | 18px |
| ヘッダーの高さ | 84px | 72px |
| トップH1 | 36px | 28px |
| アプリ詳細H1 | 42px | 34px |
| サポート一覧H1 | 32px | 28px |
| サポートとポリシーH1 | 30px | 26px |
| トップの上下余白 | 44px / 48px | 34px / 36px |

トップH1は行間1.3、字間は控えめ。長い英語は単語の途中で強制改行せず、読みやすい位置で折り返す。本文は1.7〜1.9程度の行間を基本とする。

## 一覧と詳細

- デスクトップの一覧は3列、760px以下は1列。カード全体を詳細へのリンクにする。
- 画像枠は角のある矩形。現在の比率はデスクトップ約1.12、モバイル約1.16。全カードで統一する。
- 詳細では名前・説明・App Store導線を上部に置き、機能や仕様を読む前にも行動できるようにする。
- 審査中のアプリは一覧・詳細に審査中と明記する。ストアリンク、無料価格、公開バージョンは掲載せず、検索向け構造化データにもダウンロード可能と記載しない。
- 詳細の左端に背景画像のぼかしを置く。本文領域には画像や模様を重ねない。
- サポートには問い合わせ先を明示する。現在は `support@mtk.sh` へのメールリンクで、件名にアプリ名を入れる。問い合わせ管理システムや送信フォームは実装していない。

## 言語と検索のための構造

日本語・英語・簡体字中国語のページを用意する。サイトの翻訳と、アプリ内で対応する言語を別々に表示する。言語を切り替えても、同じアプリ・同じページ種別に留まる。

タイトル、説明文、canonical、hreflang、サイトマップ、構造化データをページごとに生成する。FAQは本文として読める形で掲載し、アプリの仕様に基づいて答える。レビュー件数や評価など未確認の数値は追加しない。

SEO記事は今後、英語で検索される具体的な課題を扱う。現在の紹介ページを増やすことと、検索向けの記事を作ることは別の作業として管理する。

## アクセシビリティと動き

各ページにH1を1つ置き、本文へのスキップリンクとキーボードフォーカスを保つ。装飾画像のaltは空にし、実画面には内容を識別できる代替テキストを付ける。FAQと対応言語の展開には標準のdetails要素を使う。

ホバーは画像を少し持ち上げる程度。動きを減らす設定を尊重する。390px幅とデスクトップ幅で横方向のはみ出し、見出しの折り返し、言語メニュー、App Store・サポートへの導線を確認する。
